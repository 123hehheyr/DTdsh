# Agent Note: 组合包与插件展示元信息

Status: implemented

[English](2026-09-28-bundle-and-plugin-display-metadata.md) | 中文

## 问题

一个包可以导出多个插件。它的 npm 介绍和图片标识整个包，不一定适用于每个导出的插件。展示文本也必须在激活前及插件加载失败后保持可用。

## 决策

普通插件复用导出 locale JSON 中的 `meta.title` 和 `meta.description`，不为展示文本或自定义图片读取包清单。[本地化元信息决策](2026-09-18-localized-package-metadata.zh.md)继续约束 locale 资源身份、英文发现入口、逐字段语言回退、诊断与不激活读取；本文取代其中普通插件的包字段回退。

组合包使用相同的 locale 资源，还可以读取导出的包清单文本和图标。清单 `icon` 字段保留既有的相对路径含义并优先使用；只有省略它时才启用独立的 `./icon` 资源。Node exports 选择 locale 和后备图标路径，因此作者可以移动资源而不改变公开的资源地址。导出的后备图标无需导出清单。[包开发指南](../../../../docs/cookbook/adding-a-package.zh.md#plugin-display-metadata)负责说明作者格式与图片限制。

管理器传入它已经解析出的组合包目录。清单图标必须留在声明清单所在目录内，清单被重定向时也一样。导出的后备图标必须留在组合包的真实根目录内，允许平行的资源目录，但拒绝指向包外的符号链接。已声明的图标无效时返回诊断，不丢弃有效文本，也不尝试低优先级的导出。普通插件行及其详情使用通用插画。

元信息查询不执行插件入口。禁用或加载失败的插件仍保留 locale 文本，每个完整插件模块名及其解析父地址保持独立的资源身份。发布检查同时验证普通插件 locale、组合包 locale、选中的图片资源及发布文件覆盖。

## 考虑过的替代方案

**导出 JavaScript `meta` 值。** 读取它需要执行模块，使元信息依赖加载。现有 locale JSON 已支持禁用插件和独立的子路径元信息。

**为所有插件使用包元信息。** 包级介绍或图片不一定描述它导出的每个插件。普通插件拥有自己的 locale 文本，组合包拥有包级展示资源。

**只使用图标导出。** 替换清单字段会使现有组合包声明失效。导出资源是优先级较低的补充，保留已有声明及其相对路径。

**要求后备图片同时导出清单。** 文本回退和导出图片的发布相互独立。已经解析的组合包根目录无需暴露另一项资源即可限制导出图片的路径。

## 验证

针对性读取器和发布测试覆盖清单优先级、重定向的既有清单、导出的后备目标、缺失导出、无效资源、大小限制、路径限制，以及普通插件只读 locale 的行为。消费方和浏览器测试覆盖禁用行的本地化文本、不同的清单与导出图片、普通插件通用插画和保留的诊断。

## 影响

现有组合包图标声明无需迁移。作者可以添加 `exports["./icon"]` 作为低优先级的替代来源，并将目标加入 `files`。普通插件作者若希望插件行显示包描述文本，应将其发布到 locale `meta.description`；否则不显示描述。Host 不额外执行 JavaScript，也不需要 Cordis 或 Loader 元信息 API。Session 日志和管理工具的展示字段排除规则保持不变。
